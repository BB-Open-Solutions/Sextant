# UI audit, August 2026

Audit item C2: the console's interface, **excluding** accessibility, which has
its own document and its own ratchet
(`docs/compliance/accessibility-audit.md`, `internal/http/web/a11y_test.go`).

Scope: translation completeness, empty states, and whether either can rot
without anybody noticing. Measured 2026-08-10 against the templates and the
message catalog rather than by clicking through the console.

Short version: **nothing here was broken, and nothing was keeping it that
way.** The findings are about the absence of guards, not the presence of
defects, and the work was to turn two good measurements into two tests.

## What was measured

| | |
|---|---|
| Catalog keys defined | 975 in `en`, 975 in `nl` |
| Distinct keys used by templates and Go | 878 |
| Used but undefined | **0** |
| Defined in one locale only | **0** |
| Templates with an empty state | 29 of 32 |

## F1 - a missing translation is a word on the screen, not an error

`Localizer.T` falls back to English and then **returns the key itself**
(`internal/http/web/i18n.go:53`). A key that does not exist renders
`devices.config_frobnicated` into the page. Nothing fails, nothing is logged,
and the first person to find out is a user reading a variable name.

Today nothing is missing. The risk is entirely about tomorrow, and it is not
theoretical, because of the next finding.

**Closed** by `internal/http/web/i18n_keys_test.go`.

## F2 - some keys are built at runtime, where no static check can see them

`TestCatalogParity` compares the two locales against each other, which catches
a half-translated entry and cannot catch a key nobody defined at all. A scan of
the templates catches the literals. Neither sees this:

```
{{$.L.T (printf "devices.config_%s" $cs)}}
```

or the keys handed in from Go as struct fields - `TitleKey`, `StepKeys`,
`StatusKey`. Adding a case to `deviceConfigState` is a one-line change in a
file with nothing to do with translation, and it silently invents a key.

The test drives `deviceConfigState` over **all 64 combinations of its six
inputs** and asserts every state it can reach has a key in both locales,
rather than restating the constants in the test - a second list to keep in
step is how this class of bug arrives in the first place. Five states are
reachable; all five are translated.

`statusMeta` (`pipeline.go`) is the same shape and is already safe: its
`default` returns a real key rather than the raw status, so an unknown status
degrades to "planned" instead of printing itself. Worth copying.

**Closed** by the same test file.

## F3 - empty states are fine, and the obvious metric is misleading

98 of 121 `{{range}}` blocks have no `{{else}}`. That number means nothing:
almost all of them are inner loops over tags, columns and options, where an
empty state is not a concept.

Per page it is healthy. 29 of 32 templates carry either an `{{else}}` branch
or a dedicated `*.empty` key. The three without - `assurance_confirm.html`,
`org.html`, `secret_reveal.html` - are confirmation and detail screens with no
list on them.

**No action.** Recorded so the next person who runs that grep does not report
98 findings.

## Not covered here

- **Small screens.** Not measured. Needs rendering, not grepping.
- **Error message quality.** Whether a refused form says what was wrong, where,
  and in text rather than colour, is WCAG 3.3.1 and belongs to the manual
  accessibility round, which has no owner.
- **Anything a person sees.** This audit proves the machinery is consistent. It
  does not prove the console is pleasant, and no static check will.
